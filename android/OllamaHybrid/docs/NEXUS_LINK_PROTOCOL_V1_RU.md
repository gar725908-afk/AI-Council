# NEXUS LINK — спецификация протокола v1

Первый пункт этапа LFC-4. Описывает, как телефон NEXUS и агент на ПК
образуют локальную пару **без публичного сервера и без облачного аккаунта**.

Android-сторона ядра протокола реализована (`nexus/LinkProtocol.kt`, 15
юнит-тестов). Транспорт и Desktop Agent — отдельная работа, см. «Что не
сделано» в конце.

## 1. Принципы

1. **Deny-by-default.** Пока пользователь не выдал именованную возможность,
   телефон не может вызвать на ПК ничего. Произвольный shell/PowerShell,
   cookies браузера, домашний каталог и ключи **не существуют как
   возможности** — их нельзя запросить даже теоретически.
2. **Только локальная сеть.** Discovery через mDNS в той же LAN. Публичного
   relay-сервера нет и не будет. Wi-Fi сначала, USB позже.
3. **Взаимное подтверждение.** Шестизначный код показывается на обоих
   устройствах, пользователь сверяет их глазами.
4. **Привязка к сертификату.** Ключ сессии выводится из кода, обоих nonce и
   отпечатка сертификата ПК, поэтому подмена узла рвёт сессию.
5. **Всё журналируется.** Каждый вызов проходит те же одобрения и аудит, что
   и локальные инструменты Bridge.

## 2. Обнаружение

- Тип службы: `_nexus-link._tcp`
- ПК публикует: имя агента, версию протокола, отпечаток сертификата.
- Телефон показывает найденные узлы; автоматического подключения нет.

## 3. Возможности (scopes)

| id | Что открывает | Опасная |
|---|---|---|
| `council` | AI Consilium на ПК | нет |
| `mcp_tools` | MCP-инструменты ПК | нет |
| `workspace_read` | Чтение рабочей папки проекта | нет |
| `workspace_write` | Запись в рабочую папку проекта | да |
| `build_jobs` | Сборочные задания | да |
| `browser_automation` | Автоматизация браузера (Playwright) | да |

**Запрещённые навсегда:** `shell`, `powershell`, `cmd`, `exec`, `cookies`,
`home`, `filesystem`, `root`, `keychain`, `credentials`, `ssh`. Тест
`forbidden capabilities can never be granted or invoked` следит, чтобы ни одна
из них не появилась в перечислении и не прошла проверку доступа.

## 4. Рукопожатие

```
Телефон                                  ПК (Desktop Agent)
   |  mDNS discovery                        |
   |--------------------------------------->|
   |  PairingRequest {version, device,       |
   |    nonce_phone, requested_scopes}       |
   |--------------------------------------->|
   |                     код 6 цифр на обоих экранах
   |  PairingOffer {version, agent,          |
   |    nonce_agent, granted_scopes,         |
   |    cert_fingerprint}                    |
   |<---------------------------------------|
   |  пользователь сверяет коды              |
   |  session_key = SHA-256(                 |
   |    "nexus-link:v1:" + code + nonce_phone|
   |    + nonce_agent + fingerprint)         |
```

### Условия отказа (все проверяются и покрыты тестами)

| Условие | Поведение |
|---|---|
| Коды не совпали | Отказ: «Коды на телефоне и компьютере не совпадают» |
| Прошло больше 120 с | Отказ: окно сопряжения истекло |
| nonce сторон одинаковы | Отказ: возможна атака повтора |
| Короткий или отсутствующий nonce | Отказ: недостаточно случайности |
| Нет отпечатка сертификата | Отказ |
| ПК выдал возможности, которых телефон не просил | Отказ |
| ПК не выдал ни одной возможности | Отказ |
| Версия протокола не совпала | Предложение не разбирается |

## 5. Вызовы после сопряжения

Каждый запрос несёт id возможности. Перед отправкой телефон проверяет
`isAllowed(granted, scope_id)`; отсутствие возможности в выданном наборе
означает отказ на стороне телефона, не дожидаясь ответа ПК. Опасные
возможности дополнительно требуют одноразового подтверждения пользователя
через Gateway, как и привилегированные локальные инструменты.

## 6. Требования к Desktop Agent

- deny-by-default, типизированные запросы, allowlist путей;
- ограничение времени и объёма вывода на каждую операцию;
- отдельный журнал на стороне ПК;
- подтверждение для опасных действий;
- запрет экспонировать shell, cookies, домашний каталог и MCP без авторизации;
- не требует немедленных изменений в существующем desktop-проекте на Python.

## 7. Что сделано и что нет

**Сделано (Android):** модель возможностей с запрещённым списком, генерация
кода и nonce, полное рукопожатие с восемью условиями отказа, вывод ключа
сессии с привязкой к сертификату, проверка доступа deny-by-default, формат
сообщений и разбор предложения ПК. 15 юнит-тестов.

**Не сделано:** сам транспорт (mDNS-обнаружение и TLS-канал на устройстве) и
**Desktop Agent для ПК** — отдельная программа, которую нельзя написать и
проверить из облачной среды: требуется реальная пара «телефон + компьютер» в
одной сети. ТЗ прямо ставит Desktop Agent отдельной веткой после согласования
с состоянием desktop-проекта.
