# NEXUS MODEL CENTER и NEXUS EVOLUTION

Статус: базовые runtime-адаптеры, загрузчик, экран Model Center и исполнитель Evolution добавлены в Android-ветку. Сборка, запуск и испытания на физическом устройстве намеренно отложены до отдельного этапа.

## 1. Назначение

NEXUS MODEL CENTER отвечает за выбор локальной модели, получение весов, импорт файлов, проверку целостности, хранение и активацию. Веса не входят в APK и не скачиваются автоматически.

Поддерживаются два on-device runtime:

- **LiteRT-LM** — Android runtime для файлов `.litertlm`. В проект закреплена зависимость `com.google.ai.edge.litertlm:litertlm-android:0.16.1`; выбор этой версии согласован с текущим Kotlin 2.2.20 toolchain. Начальная конфигурация движка — CPU backend. Аппаратное ускорение и NPU/GPU пока не включены в обещания совместимости.
- **llama.cpp** — GGUF runtime через JNI/NDK и CMake. Исходный проект llama.cpp закреплён на release tag `v1.0.0`; ABI `arm64-v8a` (для эмулятора CI ещё `x86_64`), только CPU, Android GPU offload не заявлен.
  - Движок всегда собирается с оптимизацией (`-O3`, `Release`), в том числе внутри debug-APK — сборка `-O0` отвечала в разы медленнее.
  - CPU-часть ggml — отдельные библиотеки под разные процессоры: ARMv8.0, v8.2 + dotprod, v8.2 + fp16, v8.6 + i8mm, v9 + SVE2/SME. При первом запуске модели выбирается лучшая для этого телефона (`ggml_backend_load_all_from_path`, как в официальном Android-примере llama.cpp); KleidiAI включён. Что выбрано — видно в Model Center («Движок GGUF: llama.cpp · CPU: …») и в профиле узла Mesh.
  - Библиотеки выровнены под страницы 16 КБ (Android 15+) и распаковываются при установке (`useLegacyPackaging`), чтобы их можно было найти в папке приложения.

Оба движка реализуют общий `ModelGateway`, используемый AI Studio и доступный для маршрутизации Council через выбор локального provider profile. On-device inference не использует платный API и не зависит от домашнего ПК.

## 3. Загрузка и хранение весов

`NexusModelStorage` реализует:

- отдельный каталог файлов в приватном хранилище приложения;
- потоковую загрузку по HTTPS, включая HTTPS redirects, которые используются хранилищем моделей;
- проверку свободного места, заявленного размера и точной принятой лицензии;
- расчёт SHA-256 во время записи, ограничение максимального размера и fsync;
- временный файл до окончания проверки и атомарное перемещение в каталог моделей;
- отмену загрузки; отменённый/неполный файл не регистрируется;
- реестр установленных моделей и одну выбранную активную модель;
- импорт `.gguf` и `.litertlm` через системный picker с копированием в app-private storage и расчётом SHA-256;
- проверку GGUF magic header для импортируемых GGUF-файлов.

Сейчас отменённую загрузку нужно запускать заново: возобновление с offset (pause/resume) ещё не реализовано. Хранилище закрыто от других приложений Android по умолчанию; экспорт моделей отдельно не добавлен.

## 4. Экран Model Center

В нижней навигации NEXUS открыт раздел **Модели**. Он содержит:
- каталог и рекомендации;
- карточки с runtime, назначением, размером, revision и SHA-256;
- явное принятие лицензии перед скачиванием;
- ход загрузки и её отмену;
- активацию и удаление неактивных файлов;
- импорт собственных `.gguf` и `.litertlm` файлов;
- сведения об активной локальной модели;
- вкладку Evolution с предложениями, одобрением, журналом версий и откатом.

Важно: в текущей версии встроенный prompt format llama.cpp ориентирован на Qwen3 ChatML. Произвольный GGUF может иметь другую chat template и не обязан корректно работать только потому, что файл прошёл проверку GGUF-заголовка. Для универсального импорта нужен отдельный механизм получения и применения template из metadata модели.

## 5. Подключение к AI Studio и Council

Добавлены provider profiles:
- `ON_DEVICE_LITERT`;
- `ON_DEVICE_LLAMA_CPP`.

Эти варианты не требуют API endpoint и ключа. Модель и runtime выбираются в Model Center; AI Studio использует активный файл соответствующего runtime. Если активная модель относится к другому runtime, движок возвращает понятную ошибку вместо попытки сетевого fallback.

Существующие удалённые профили и Ollama LAN остаются отдельными транспортами. Модель, запущенная на ПК через Ollama, всегда является `HOME_PC_LAN / NETWORK_ENDPOINT`, а не `ON_DEVICE`.

## 6. NEXUS EVOLUTION

`NexusEvolutionExecutor` хранит:
- предложения с причиной изменения и payload;
- тип изменения: prompt profile, skill pack, routing policy, tool description или model configuration;
- SHA-256 payload;
- монотонные ID версий и связь с родительской версией;
- активную версию, архив payload и JSONL audit trail;
- явное подтверждение перед активацией;
- отклонение предложений и откат на сохранённую предыдущую версию.

Активные prompt profiles и skill packs подключены к системному контексту AI Studio и Council. При откате конфигурации разрешаются по цепочке родительских версий, чтобы изменения из более поздней ветви не оставались включёнными.

**Рабочая интеграция routing policy:** тип `ROUTING_POLICY` теперь имеет строгую JSON-схему v1. Она принимает только известные восемь ролей Council, значения из `ProviderKind` и необязательные model ID overrides. Неизвестные поля, endpoint URLs, API keys, неизвестные роли и некорректные provider values отклоняются при создании предложения и повторно перед активацией. В AI Studio активная Evolution policy имеет приоритет над сохранёнными per-agent routes и model overrides. В Model Center добавлен шаблон схемы.

**Ограничения текущего executor:** `TOOL_DESCRIPTION` и `MODEL_CONFIGURATION` пока хранятся как версионируемые предложения, но не подключены к исполняемым tool adapters или параметрам генерации. Они не дают модели новых полномочий и не изменяют runtime автоматически.

Evolution не исполняет произвольный код, не меняет права Android, security policy, trusted keys или веса нейросети. Fine-tuning и замена модели — отдельный процесс Model Center с отдельным согласием.

## 7. Что отложено до будущего этапа

Согласно текущему решению, функциональные и физические испытания пока не запускаются. Отдельно остаются:

1. Чистая Gradle/NDK сборка и устранение ошибок компиляции, если они обнаружатся.
2. Проверка ABI/runtime на конкретной модели Android-телефона.
3. Загрузка Gemma и Qwen на реальном устройстве, открытие файла движком и генерация.
4. Замеры RAM, скорости, температуры, батареи, времени холодного старта и стабильности длительной генерации.
5. Проверка отмены, недостатка места, прерывания сети, неправильного checksum и восстановления после перезапуска.
6. Интеграционные проверки Evolution: цепочки нескольких типов изменений, подтверждение, откат и корректность активного контекста.
7. Универсальные chat templates для разных GGUF, дополнительные модели и FunctionGemma с проверенными артефактами.

CI workflow на этом этапе оставлен для сборки debug APK; автоматический unit-test step отложен. Это не означает, что сборка или APK уже подтверждены. Установка на физический телефон и runtime-проверки не выполнялись.

## 8. Принципы сохранности

- Разработка ведётся в `nexus/genesis-foundation`.
- `main` не изменяется.
- Desktop Python/PySide6 проект не изменяется.
- Веса моделей не включаются в Git или APK.
- Секреты, токены и пользовательские учётные данные не сохраняются в репозитории.
