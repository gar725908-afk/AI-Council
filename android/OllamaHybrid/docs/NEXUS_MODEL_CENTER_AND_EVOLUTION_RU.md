# NEXUS MODEL CENTER и EVOLUTION

Статус: реализована основа каталога и политик; inference runtimes, UI, скачивание и активация моделей — следующие этапы.

## Назначение

NEXUS должен позволять выбирать, загружать, хранить, переключать и удалять совместимые локальные модели, а также обнаруживать модели домашнего ПК через Ollama. Gemma 4 E2B — рекомендуемый кандидат для Android Balanced-профиля, но не единственная модель и не обязательная зависимость APK.

## Начальный каталог

- **Gemma 4 E2B** — рекомендуемый кандидат на телефоне. E2B обозначает effective-2B tier; это не обещание, что любой формат имеет ровно два миллиарда активных параметров. До публикации конкретного бинарного артефакта нужно проверить модельную карточку, экспорт под runtime, лицензию и совместимость устройства.
- **Qwen3 0.6B** — компактная альтернатива.
- **FunctionGemma 270M** — специализированная модель маршрутизации инструментов, не универсальный чат-менеджер.
- **Ollama LAN** — динамический список реальных моделей с домашнего ПК через /api/tags. Эти модели не скачиваются на телефон.

Каталогные записи — метаданные-кандидаты, а не заявление о том, что веса уже загружены, протестированы или доступны для установки.

## Runtime abstraction

Целевой контракт: NexusInferenceEngine с адаптерами LiteRT-LM (Android-оптимизированные модели), llama.cpp (GGUF) и OllamaLanEngine (домашний ПК). LAN-модель всегда маркируется как HOME_PC_LAN/NETWORK_ENDPOINT, а не ON_DEVICE.

## Безопасная загрузка

Модель не становится скачиваемой, пока нет проверенного manifest:
- доверенный источник и immutable revision;
- лицензия;
- точное имя и размер файла;
- SHA-256;
- совместимый runtime/формат.

Порядок: выбор варианта и квантования → показ лицензии/размера/свободного места → явное подтверждение → загрузка с pause/resume → SHA-256 verification → проверка совместимости → регистрация. Удаление модели не удаляет чаты и архив. Никакие гигабайты весов не включаются в APK и не скачиваются автоматически.

Для Balanced-профиля на устройстве с 12 ГБ RAM стартуем с одной активной модели и динамического контекста. Фактические лимиты и скорость устанавливаются бенчмарком на реальном телефоне.

## Маршрутизация

Учитываются режим пользователя (PHONE ONLY / HOME PC / HYBRID / OFFLINE), приватность/согласия, доступность узла, совместимость runtime, свободная память, температура, батарея, latency и возможности модели. Если PC Ollama недоступна, скрытый cloud fallback запрещён: NEXUS предлагает on-device модель или assisted/manual режим.

## EVOLUTION — контролируемое саморазвитие

Саморазвитие означает улучшение проверяемых слоёв NEXUS: skill packs, prompt profiles, routing policies, tool descriptions, memory retrieval settings и evaluation tests.

Цикл: наблюдение с evidence → предложение с обоснованием и diff → тесты/регрессии → явное одобрение пользователя → версионированная активация → audit log и rollback.

Изменение весов LLM (fine-tuning, замена модели или квантования) — отдельная процедура Model Center с отдельным согласием, источником, лицензией, checksum, оценкой качества и возвратом к предыдущей версии. Модель не может сама менять security policy, разрешения, trusted keys или Recovery Core.

## Реализовано в foundation

- Типизированный каталог Gemma 4 E2B, Qwen3 0.6B, FunctionGemma 270M и динамического Ollama LAN.
- Capability, runtime, execution target и install-state модели.
- Manifest с source, immutable revision, license, file name, size и SHA-256.
- Download policy: запрет без проверенного manifest, места и принятия точной лицензии.
- Evolution proposal: версии, SHA-256, обязательное одобрение и rollback point.
- Unit tests для каталога, download policy и evolution approval.

## Пока не реализовано

LiteRT-LM/llama.cpp inference adapters, downloader/worker, runtime installation, Model Center UI, persistent registry, device benchmark, evolution storage/executor, автоматическое fine-tuning. Записи без manifest не скачиваются.
