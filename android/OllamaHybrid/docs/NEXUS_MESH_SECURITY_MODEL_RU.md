# NEXUS Mesh — модель безопасности

Цель: телефоны владельца доверяют только друг другу, посторонний не может ни
выполнить задачу, ни прочитать трафик, ни выдать себя за телефон владельца.
Все утверждения ниже соответствуют коду `mesh/*.kt` и проверяются тестами
`MeshNodeTest` / `MeshProtocolTest`, если не сказано иное.

## Что защищаем

| Актив | Где живёт | Защита |
|---|---|---|
| Закрытый ключ устройства (EC P-256) | Android Keystore, алиас `nexus-mesh-identity-v1`, не экспортируется | Ключ не покидает Keystore; на телефонах с защищённым чипом (TEE/StrongBox) — аппаратно; UI честно показывает, какой вариант |
| Список доверенных устройств | приватные настройки приложения `nexus_mesh_trust` | Только публичные данные: отпечаток, ID, имя, права, адреса, даты. Секретов нет |
| Секрет приглашения (16 байт) | память пригласившего ≤ 10 мин; ссылка/QR у владельца | Одноразовый, не передаётся по сети (только HMAC-доказательство) |
| Текст задач и ответов | канал TLS; история задач на телефонах | Шифрование канала; история — в приватном хранилище приложения, ответы обрезаны |
| Ключи API ядра ИИ | Android Keystore (AES-GCM), см. `AndroidCredentialVault` | Никогда не отправляются в Mesh. Облачное ядро для чужих задач выключено по умолчанию |
| Заряд, нагрев, ресурсы телефона | — | Resource Governor до принятия задачи |

## Модель нарушителя и ответы

| Нарушитель | Что может попытаться | Что происходит |
|---|---|---|
| Посторонний в той же Wi-Fi | Подключиться к порту 47811 | TLS с обязательным клиентским сертификатом; без доверия разрешён только запрос сопряжения по живому приглашению. Не больше 10 недоверенных подключений в минуту |
| Тот же — пассивно | Слушать трафик | Видит факт соединения и объём; содержимое зашифровано TLS 1.3/1.2 с ECDHE + AEAD |
| Тот же — mDNS | Увидеть объявления | Видит, что в сети есть узел NEXUS, его ID и 16 hex отпечатка (публичные данные). Объявление ничего не открывает |
| Посредник (ARP-spoofing) при сопряжении | Встать между телефонами | Присоединяющийся закрепил ключ пригласившего из ссылки — подменённый ключ отвергается. Доказательство знания секрета связано с ключами конкретного TLS-соединения. Плюс 6-значный код, который владелец сверяет на обоих экранах |
| Тот, кто перехватил ссылку (пересылка через чужой чат) | Успеть присоединиться за 10 минут | На пригласившем телефоне появится запрос от чужого устройства с кодом, которого нет на втором телефоне владельца → «Отклонить». Приглашение одноразовое |
| Подбор секрета | Перебирать `proof` | 3 ошибки — приглашение уничтожается; 128-битный секрет |
| Атакующий из интернета | Подключиться напрямую | Узел не открывает портов в роутере; соединения с публичных адресов отклоняются до TLS и пишутся в журнал |
| Потерянный или украденный телефон владельца | Давать задачи другим телефонам | «Отозвать» на остальных телефонах — соединение рвётся сразу, новые подключения от этого ключа принимаются только как несопряжённые |
| Скомпрометированный доверенный телефон | Отправлять задачи | Только три типизированные операции, в пределах прав (`grants`) и Governor'а. Командной строки, файлов, произвольного кода нет |
| Тот же | Читать то, что ему отправили | **Может.** Шифруется канал, а не вычисление. Не отправляйте пароли и приватные документы устройству, которому не доверяете |
| Другое приложение на том же телефоне | Подключиться к 127.0.0.1:47811 | То же, что посторонний: нужен ключ из списка доверенных или живое приглашение с подтверждением владельцем на обоих экранах |
| Тот же | Прочитать ключ | Ключ Android Keystore привязан к приложению NEXUS |
| Злонамеренный узел | Прислать огромный или кривой кадр | Кадр ≤ 256 КиБ, закрытая схема, лимиты длин полей; при нарушении — разрыв |
| Флуд из локальной сети | Держать много соединений | Каждое недоверенное соединение ограничено 20 с рукопожатия; узел не падает, но может стать временно недоступен. Это известное ограничение (см. ниже) |

## Принципы, которые соблюдены

- Свою криптографию не изобретаем: TLS платформы (Conscrypt/BoringSSL),
  ECDSA P-256, HMAC-SHA256, SHA-256, `SecureRandom`.
- Закрытые ключи не хранятся в SharedPreferences, файлах или логах.
- Никаких API-токенов и паролей между телефонами. Профиль `node.status`
  содержит только название ядра и модели.
- Никакого исполнения произвольных команд на удалённом устройстве.
- Порты llama.cpp RPC, Ollama и внутренних API в интернет не выставляются.
  Ollama доступна другим телефонам только опосредованно — через задачу
  `inference.run` узла NEXUS.
- Соединение не называется установленным до завершения TLS и обмена `hello`;
  сопряжение не считается состоявшимся до двух подтверждений.
- Журнал безопасности (200 последних событий): старт узла, приглашения,
  запросы и отказы сопряжения, блокировки публичных адресов, неудачные
  рукопожатия, отказы задач Governor'ом, отзывы.

## Известные ограничения

- **Доверие к ссылке.** Если ссылку перехватили и владелец подтвердил чужой
  запрос, не сверив код, чужое устройство станет доверенным. Защита —
  сверка 6 цифр на **обоих** телефонах; интерфейс это требует явно.
- **Флуд в локальной сети** может временно занять узел. Ограничения есть
  (тайм-ауты, лимит недоверенных), но полностью от DoS в общей сети не защищают.
- **Ротация ключа** не реализована: ключ живёт, пока установлено приложение.
  Переустановка = новый ключ = новое сопряжение.
- **Отзыв локальный.** Отзыв на телефоне A не распространяется на телефон C
  автоматически — отзывать нужно на каждом телефоне (сеть без центра).
- **Данные исполнителю видны** (см. таблицу). Конфиденциальные вычисления
  на чужом телефоне невозможны без TEE-аттестации — это не делается.
- **Android 17+** потребует разрешение доступа к локальной сети для приложений
  с targetSdk 37+ — учесть при обновлении targetSdk.
- Проверка на физических телефонах не выполнена.
