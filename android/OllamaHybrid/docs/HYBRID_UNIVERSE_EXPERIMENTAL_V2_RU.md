# OllamaHybrid — Hybrid Universe / Experimental Edition
Версия: 2.0  
Статус: концепция и подробная спецификация интерфейса. Не является подтверждением реализации экранов или готовности APK.

## 0. Решение по направлению

**Выбранная вселенная: Hybrid Universe. Интенсивность: Experimental.**

OllamaHybrid — не «чат с неоном», а персональная цифровая операционная среда: командный мост, где человек управляет моделями, агентами, браузером, знаниями и возможностями Android.

Визуальный синтез:
- **Blade Runner / Black Lotus:** атмосферный неон-нуар, мокрый город, глубина, контровой свет, ощущение искусственной жизни.
- **The Expanse / Leviathan Wakes:** инженерная достоверность, корабельные приборы, техническая маркировка, функциональная телеметрия.
- **Ghost in the Shell:** цифровое сознание, кибернетические связи, слои информации, сеть как пространство.
- **TRON:** световая архитектура и геометрия цифрового мира.

Это оригинальная визуальная система, а не копирование кадров, интерфейсов, логотипов или графических ресурсов произведений.

**Экспериментальность = выразительная композиция + реактивная визуализация реальных процессов + необычная навигация.** Не экспериментировать с читаемостью, безопасностью или предсказуемостью действий.

## 1. Дизайн-манифест

1. **Система выглядит живой, но не притворяется живой.** Свет, движение, линии связей и активность появляются только по реальным событиям приложения.
2. **Интерфейс имеет глубину.** Фон, рабочая поверхность, плавающие инструменты и контекстные слои визуально различимы.
3. **Каждый модуль — отдельная среда.** Command Deck — мост управления; AI Studio — пространство диалога; Council — нейронная сеть; Browser — цифровой портал; Device Core — машинное отделение.
4. **Неон — семантика.** Cyan = управление/навигация; violet = AI/рассуждение; magenta = экспериментальный режим; green = подтверждённый успех; amber = ожидание/внимание; red = ошибка/опасность.
5. **Текст всегда выше эффекта.** Ни глитч, ни свечение, ни текстура не проходят под длинным текстом и не снижают контраст.
6. **Честная телеметрия.** Неизвестно — значит «нет данных», а не выдуманное число или декоративная анимация.

## 2. Визуальная грамматика

### 2.1 Слои пространства

- **Void Field:** почти чёрный фон с едва заметной глубиной, без шумной текстуры.
- **Atmosphere:** редкие световые градиенты у краёв, лёгкая виньетка и статичные архитектурные линии.
- **Work Plane:** основная поверхность с высокой контрастностью и чёткой сеткой.
- **Floating Instruments:** панели инструментов, инспекторы и bottom sheets, которые появляются по контексту.
- **Signal Layer:** линии маршрутов, индикаторы активности, точки событий. Не перекрывают контент и не перехватывают касания.

Не применять blur к большим полноэкранным областям постоянно. Для «стекла» использовать непрозрачную или почти непрозрачную поверхность; blur — только локально и при аппаратной доступности.

### 2.3 Форма и геометрия

- Основная сетка: 4 dp; шаги компоновки 8/12/16/20/24/32 dp.
- Радиусы: 8 dp для полей, 12 dp для карточек, 18 dp для крупных поверхностей, 26 dp для модальных листов.
- Использовать срезанные углы только как редкий фирменный мотив: бейджи, верхний угол панели, маркеры активного модуля. Не срезать все карточки.
- Тонкая техническая рамка, двойной контур или внутренний маркер допустимы для ключевой панели.
- Минимальная область касания — 48 × 48 dp; декоративная линия не должна становиться ложной кнопкой.

### 2.4 Типографика

- Основной интерфейс: системный sans-serif Android, динамический масштаб шрифта.
- Технические данные: моноширинный шрифт, только для URL, логов, ID, токенов и показателей.
- Цифры телеметрии — tabular numerals.
- Заголовки короткие, с нормальным регистром; капс — только для коротких технических меток.
- Не использовать узкие sci-fi шрифты для основного текста.
- Строки не обрезать без доступного раскрытия полного значения.

### 2.5 Фирменные графические мотивы

- **Neural Constellation:** точки агентов и реальные связи между ними.
- **Orbital Rings:** кольцевая визуализация состояния ядра/выбранной модели; сегменты означают только измеренные состояния.
- **Signal Traces:** тонкие маршруты передачи команды между UI, оркестратором, инструментом и моделью.
- **Telemetry Rulers:** шкалы для измеримых параметров, с единицами и временем обновления.
- **Holo Markers:** контурные метки для локальной/облачной модели, привилегий и статусов.

Запрещено изображать процент готовности, скорость, токены/с или загрузку CPU/GPU, если соответствующий источник реально не подключён.

## 3. Motion language — движение как обратная связь

- Tap/selection: 100–160 ms.
- Смена состояния карточки: 160–220 ms.
- Появление панели: 220–280 ms.
- Переход между рабочими пространствами: 180–260 ms.
- Никаких обязательных длинных интро и блокирующих заставок.
- Никакого постоянного параллакса при прокрутке.
- Частицы, scanline и glitch включаются только в отдельных акцентных состояниях и имеют статический fallback.
- Учитывать Android Animator duration scale и системное уменьшение анимации.
- В фоне анимации приостанавливать; при энергосбережении переходить в Static Mode.

### Реактивные состояния ядра

| Состояние | Реальный триггер | Визуальное поведение |
|---|---|---|
| Standby | Нет активных задач | Спокойное кольцо, статичный статус |
| Listening | Пользователь вводит/диктует команду | Тонкая пульсация контура |
| Routing | Оркестратор выбирает модель/инструмент | Короткий маршрутный импульс |
| Thinking | Есть подтверждённый streaming/processing state | Мягкое вращение сегмента |
| Tool Active | Инструмент реально выполняется | Подсветка соответствующего узла |
| Awaiting Approval | Требуется решение пользователя | Amber-контур и явная кнопка |
| Completed | Получено подтверждение завершения | Короткий зелёный импульс, затем standby |
| Error / Offline | Ошибка или недоступность | Статичный alert marker, текст причины |

Если backend не предоставляет эти события, показывать только фактическое доступное состояние.

## 4. Навигация: Digital Spaces

На телефоне — нижняя навигация из пяти направлений:
1. **Deck**
2. **Studio**
3. **Council**
4. **Browser**
5. **Core**

Models открывается из активной модели и Deck; Library, Downloads, History, Automations, Permissions и Settings доступны через Core/More. Не делать 8–10 мелких пунктов внизу.

На планшете и в landscape — Navigation Rail с подписью; рабочая область может иметь инспектор справа. Внутренние вкладки Browser не смешивать с глобальной навигацией.

Переход между разделами сохраняет scroll position, черновик и локальное состояние экрана. Долгоживущие сущности хранятся в репозиториях, не в памяти Composable.

## 5. Конкретные экраны

## 5.1 COMMAND DECK — Bridge / главный экран

**Назначение:** мгновенно понять, что доступно, и начать задачу.

Компоновка:
- Верхняя строка: компактный знак OllamaHybrid, подпись текущего пространства, системный статус, кнопка профиля.
- Центральный **Core Orbital**: фирменный круговой индикатор с названием активного профиля и реальным состоянием ядра. Не занимает более трети высоты первого экрана.
- **Command Portal:** широкое поле «Задайте задачу или команду»; кнопки вложения, микрофона и отправки; при фокусе — расширение composer.
- **Active Route:** строка «Задача → модель → инструменты» с реальными значениями, например Local / Cloud / Council.
- **Live Systems:** три компактных плитки: Council, Browser, Device Bridge. Каждая показывает только подтверждённый статус и открывает свой модуль.
- **Recent Operations:** последние 3–5 задач с коротким статусом и временем.
- Быстрые действия в горизонтальном ряду: «Новый чат», «Запустить Council», «Открыть браузер», «Импортировать материал».

Схема первого экрана (портрет):
1. Header (56–64 dp)
2. Core Orbital (140–180 dp)
3. Command Portal (96–132 dp)
4. Active Route (32–44 dp)
5. Live Systems (3 компактных модуля)
6. Recent Operations ниже прокрутки

Поведение:
- Нажатие на Orbital открывает System Overview, а не скрытое меню.
- Нажатие на плитку ведёт в соответствующий экран.
- При offline — показывать причину и доступные локальные функции.
- Не использовать фейковые «системные сканирования» при запуске приложения.

## 5.2 AI STUDIO — Neural Workspace

**Назначение:** качественная работа с одной выбранной моделью без потери контекста.

Экран:
- Верхняя панель: имя модели, provider badge LOCAL/CLOUD, соединение, переключатель.
- Под ней тонкая полоса контекста: чат/проект, доступные инструменты и privacy indicator.
- Основная область — диалог; сообщения свободно читаются, код и таблицы имеют отдельные поверхности.
- Tool events отображаются как раскрываемые шаги: «Открывает страницу», «Ищет в библиотеке», «Выполняет действие».
- Composer закреплён снизу; многострочный ввод, вложения, голос, инструменты, отправка/остановка.
- Контекстное меню ответа: копировать, поделиться, повторить, продолжить, сохранить в библиотеку (если функция реализована).

Экспериментальная деталь:
- У ответа может быть тонкий **Reasoning Route** — не скрытая цепочка мыслей, а безопасный журнал действий: какие инструменты вызывались, какие источники использовались, что подтверждено.
- На длинных задачах — сворачиваемая временная шкала, не декоративный waveform.

Смена модели:
- Модель/provider меняется без удаления чата.
- История привязана к сессии, а не к процессу модели.
- В случае несовместимости контекста предупреждать и предлагать продолжить в новом треде; не сбрасывать молча.
- Ошибка сети сохраняет текст пользователя и предлагает Retry.

## 5.3 COUNCIL — Neural Constellation

**Назначение:** показать командную работу нескольких агентов, а не просто список чат-ботов.

Верх:
- Имя задачи, Manager Agent, общий статус, elapsed time (если измеряется).
- Кнопки Pause / Resume / Stop — только если backend поддерживает эти операции.

Центральная сцена:
- Manager — центральный узел.
- Executor Agents — орбитальные узлы с короткими именами.
- Рёбра показывают реальные назначения/обмен сообщениями.
- В портретном режиме схема превращается в вертикальную карту потоков; не пытаться втиснуть широкую сеть в маленький экран.
- В планшетном режиме сеть слева, инспектор выбранного агента справа.

Нижняя область:
- Event Stream: время, агент, событие, краткое содержание.
- Agent Inspector: модель/provider, статус, назначенная задача, последнее сообщение, retry/timeout.
- Final Synthesis: общий результат, вклад агентов, ссылки/источники.

Состояния агента:
Queued, Assigned, Running, Waiting Tool, Awaiting Approval, Completed, Failed, Timed Out, Cancelled. Статус сопровождается текстом и иконкой.

Экспериментальная деталь:
- При назначении задачи линия от Manager к агенту загорается один раз.
- При возврате результата узел агента передаёт импульс к Manager.
- При ошибке соединение не исчезает молча: остаётся пунктирный след и запись события.
- Никаких движущихся линий без реального события.

## 5.4 CYBER BROWSER — Digital Portal

**Назначение:** самостоятельный полноценный браузер и единая точка доступа всех моделей к интернету.

Портрет:
- Верхний ряд вкладок — горизонтальный strip с favicon/коротким заголовком; активная вкладка визуально выделена.
- Адресная строка с URL/поиском, HTTPS-индикатором, reload, bookmark и overflow.
- Страница получает максимум доступной высоты и ширины.
- Нижняя **Agent Dock** раскрывается как sheet: Ask Page, Find, Extract, Fill Form, Navigate, Action Log.
- Явный переключатель управления: Human / AI Assist / Agent Running / Waiting for You.
- Системные элементы браузера не закрывают контент сайта.

Планшет:
- Слева вертикальный tab rail; по центру страница; справа опциональный Agent Inspector.
- Инспектор скрывается одним нажатием.

Browser surfaces:
- Tabs & Session Manager: вкладки, группы, восстановление.
- Bookmarks & Collections.
- History.
- Downloads.
- Page Find.
- Reader / zoom / copy / share.
- Permission prompts.
- Agent Action Log.

Агентный сценарий:
1. Пользователь формулирует задачу.
2. Browser получает независимый от модели session context.
3. Агент запрашивает ограниченное действие через типизированный инструмент.
4. Приложение показывает действие в Agent Dock.
5. Рискованная операция вызывает Approval Gate.
6. CAPTCHA, login, OTP и anti-bot — передача человеку.
7. События и результат сохраняются в журнале.

Архитектурный инвариант: выбор другой модели не пересоздаёт WebView/GeckoView, не очищает cookies, вкладки, историю, загрузки и browser state. Universal Internet Access Layer и BrowserSessionStore принадлежат приложению, а не провайдеру LLM.

## 5.5 MODEL LAB — Model Observatory

**Назначение:** выбор и диагностика локальных и облачных моделей.

Верх — выбранная модель как крупная техническая карточка:
- имя, provider, Local/Cloud;
- доступность endpoint;
- время последней проверки;
- default marker.

Далее — сегменты Local Models / Cloud Providers. В каждой карточке:
- модель и provider;
- доступность;
- контекст/квантование/размер — только если получены из конфигурации или API;
- действия: Select, Test, Configure, Set Default.

Диагностика разделена:
- Provider configured;
- Endpoint reachable;
- Model listed;
- Generation tested.

Не сводить эти четыре проверки в один зелёный индикатор.

## 5.6 DEVICE CORE — Machine Room

**Назначение:** прозрачный контроль возможностей телефона и уровня привилегий.

Первый экран:
- Android Bridge Profile: Standard / Shizuku ADB / Shizuku Root / Direct Root.
- Capability Matrix: функция, доступность, транспорт, требуемое разрешение.
- Device Telemetry: только реально доступные battery/storage/memory/network показатели с временем измерения.
- Recent Tool Calls: инструмент, инициатор, транспорт, результат.

Экран разрешений:
- Android runtime permissions;
- Accessibility;
- Shizuku;
- Root;
- файловый доступ и другие специальные доступы.
Для каждого: зачем нужно, что меняет, текущий статус, кнопка перехода к настройкам.

Опасные действия:
- точное описание команды/эффекта;
- область воздействия;
- обратимость;
- кнопки Cancel / Approve;
- отдельный audit event.

Никаких произвольных команд shell из текста модели. Не показывать Root Active, если проверка UID 0 не пройдена.

## 5.7 MATERIAL LIBRARY — Knowledge Vault

- Верхний поиск по материалам.
- Фильтры: All / Documents / Tables / Notes / Unsupported / Failed.
- Карточка: имя, тип, размер, дата импорта, индексный статус.
- Детали материала: preview, извлечённый текст, источник, ошибки парсинга.
- Действия: Open, Add to Context, Reindex, Remove.
- Показать поддерживаемые форматы честно; OCR/PDF/audio/video доступны только после реализации соответствующих pipeline.

Экспериментальный мотив: библиотека как «архивный отсек» — тонкие вертикальные метки категорий и индексные линии; никакого трёхмерного тяжёлого каталога.

## 5.8 DOWNLOADS & HISTORY — Activity Vault

Два логически отдельных раздела:
- Browser Downloads: файл, размер, источник, статус, прогресс, действия.
- AI Activity: задача, модель/provider, длительность, итоговый статус.

История браузера и история AI не смешиваются. Удаление, очистка и отмена загрузки требуют точного действия и подтверждения, если данные будут потеряны.

## 5.9 PERMISSION CENTER — Trust Console

Сводка:
- Granted;
- Needs Attention;
- Not Granted;
- Optional.

У каждой строки:
- название доступа;
- зачем он нужен;
- какие функции без него не работают;
- статус;
- переход в системные настройки;
- как отозвать.

Разрешение никогда не включается скрыто. Состояние после возврата из Settings перечитывается из Android API.

## 5.10 SETTINGS — System Tuning

Группы:
- Appearance: Hybrid Universe, Static Mode, Motion Intensity, Density.
- Models & Providers.
- Browser & Privacy.
- Council & Agents.
- Bridge & Permissions.
- Library & Storage.
- Notifications.
- Diagnostics & Logs.
- About / Build information.

Настройки внешнего вида:
- **Motion:** Static / Subtle / Experimental.
- **Atmosphere:** Minimal / Cinematic.
- **Density:** Compact / Comfortable.
- **Haptics:** Off / Standard.
- **Data disclosure:** показывать предупреждение, если контекст страницы уходит облачному провайдеру.

Пользователь выбрал Experimental как базовый визуальный профиль, но должен иметь возможность отключить эффекты без потери функциональности.

## 6. Общие системные элементы

- **Hybrid Topbar:** модуль, текущий контекст, системные сигналы.
- **Core Orbital:** реальное состояние ядра/задачи.
- **Command Portal:** единый command composer.
- **Signal Chip:** статус с текстом, пиктограммой и цветом.
- **Glassless Panel:** читаемая поверхность с тонким контуром; blur необязателен.
- **Agent Node:** агент, модель, задача, статус.
- **Event Rail:** лента фактических событий.
- **Approval Gate:** точное подтверждение действия.
- **Provider Badge:** LOCAL / CLOUD / CUSTOM.
- **Empty / Loading / Error / Offline / Permission Required:** единые состояния с понятным следующим шагом.

## 7. Компоновка и адаптивность

### Телефон, портрет
- Один основной столбец.
- Приоритет основного действия и страницы/диалога.
- Вторичные панели раскрываются sheet.
- Нижняя навигация остаётся постоянной, кроме полноэкранного режима страницы — там доступен жест/кнопка возврата к браузерным контролам.

### Телефон, landscape
- Скрывать второстепенные подписи, но не действия.
- Browser сохраняет адресную строку; Agent Dock можно свернуть.
- Council переходит в компактную карту.

### Планшет
- Navigation Rail.
- Две колонки там, где это помогает: Council network + inspector; Browser page + Agent Dock; Library list + preview.
- Не растягивать карточки и строки на всю ширину без необходимости.

### Большие шрифты и TalkBack
- Контент перестраивается вертикально.
- Нет критически важного текста только в графике.
- Семантические labels для Orbital, графа агентов, статусов и кнопок.
- Графические связи имеют текстовое альтернативное представление.

## 8. Производительность и инженерные ограничения

Цели проекта, подлежащие проверке на реальном устройстве:
- 60 fps на обычной прокрутке целевого устройства; при ограниченном GPU интерфейс остаётся плавным в Static Mode.
- Не использовать полноэкранный blur, тяжёлые частицы или постоянно перерисовываемые Canvas-сцены.
- Граф Council рисовать только видимую область; ограничить число одновременно анимируемых рёбер.
- Останавливать анимацию, когда экран не виден.
- Не загружать большие изображения и web assets в UI thread.
- Не блокировать навигацию при проверке модели или браузера.
- Держать события и состояние в ViewModel/Repository; Composable — отображение и пользовательские intent.
- Проверять memory churn, recomposition count, startup, battery drain и frame timing на реальном Android.
- Добавить настройки Static Mode и Reduce Motion до широкого релиза.

Бюджеты — цели, а не результаты измерений. Не заявлять о достижении, пока не выполнены профилирование и device QA.

## 11. Definition of Done

Экран считается готовым, когда:
- все видимые контролы выполняют реальное действие или disabled с объяснением;
- данные имеют определённый источник и корректное состояние загрузки/ошибки;
- навигация и черновики сохраняются;
- экран работает с увеличенным шрифтом и TalkBack;
- эффекты отключаются без функциональных потерь;
- измерены прокрутка, startup и память на реальном устройстве;
- нет фиктивных статусов, прогресса, кнопок или демонстрационных данных в production;
- рискованные операции имеют понятный confirmation gate.

**Итоговый образ:** OllamaHybrid выглядит как мост управления цифровой цивилизацией — атмосферный, пространственный, технологичный и живой. Но под визуальной оболочкой остаётся строгий инженерный продукт: понятный, быстрый, безопасный и честный в отношении своих возможностей.
