# Исследование 4 — агенты, Android Bridge, MCP

Срез: **2026-11-21**. Как проекты управляют телефоном, где они реально
исполняются и что из этого полезно NEXUS. Источники — README и код
(коммиты — в [Исследовании 1](01_ANDROID_AI_UNIVERSE_RU.md)).

## Механизмы управления Android

| Механизм | Что даёт | Ограничения | Кто использует |
|---|---|---|---|
| **AccessibilityService** | Чтение дерева интерфейса чужих приложений, нажатия и жесты | Работает на видимом экране; владелец включает вручную; Google Play ограничивает такие приложения; часть приложений (WebView, Flutter, игры) отдаёт пустое дерево | Operit, OpenDroid, Nyral, Zafiro, Phone-MCP, DroidClaw (через `adb`), **NEXUS** |
| **ADB (беспроводная отладка) на самом телефоне** | Права shell: ввод, скриншоты, виртуальные дисплеи | Android выключает беспроводную отладку при смене Wi-Fi и перезагрузке | Mika (сама включает обратно с разрешения), OpenCyvis |
| **Shizuku** | Те же права shell через Binder, без root | Нужно приложение Shizuku и его запуск после перезагрузки | Operit, OpenCyvis, Zafiro, Aether, Phone-MCP, **NEXUS** (фиксированные команды) |
| **Root** | Всё | Не на каждом телефоне; риски безопасности | Operit (включая root-виртуальные дисплеи с v1.7.1), Zafiro (перехват голосового ассистента), OmniBot (опционально), **NEXUS** (фиксированные команды) |
| **Виртуальный дисплей** | Агент работает на отдельном невидимом экране, владелец продолжает пользоваться телефоном | Нужны права shell (ADB/Shizuku/root) или системное приложение; рекомендуемый Android 14+ (Mika) | Mika (`ShellService.createVirtualDisplay(…, trusted = true)`), OpenCyvis, Zafiro, Phone-MCP (по сессии на агента), Operit |
| **MediaProjection** | Снимок экрана с согласия | Системный диалог согласия; на Android 14+ — каждый раз | OpenCyvis, DroidClaw, Operit, **NEXUS** (одноразовое согласие) |
| **ADB с компьютера** | Полный контроль без приложения на телефоне | Нужен ПК рядом или постоянно подключённый | Open-AutoGLM, DroidClaw, Mobile MCP |

## Сильные идеи, которых нет в NEXUS

1. **Виртуальный дисплей для агента** (Mika, OpenCyvis, Phone-MCP): агент
   работает, а владелец пользуется телефоном. Требует прав shell — у NEXUS
   уже есть Shizuku-транспорт, нужен виртуальный дисплей и ввод на нём.
2. **Восстановление после «залипания»** (DroidClaw): если экран не меняется 3
   шага — подсказки восстановления; счётчик повторов одинаковых нажатий;
   «дрейф» навигации без действий; скриншот вместо пустого дерева.
3. **Передача капчи человеку** (Nyral, Mika): агент останавливается и отдаёт
   страницу владельцу одним касанием.
4. **Разделение сессий и «аренды»** (Phone-MCP): у каждого агента свой
   дисплей, явное владение, отмена и очистка.
5. **NEXUS как MCP-сервер** (Zafiro, Mika, Phone-MCP): ИИ на компьютере может
   давать задачи телефону. У NEXUS для этого уже есть закрытый канал NEXUS
   Mesh и протокол NEXUS LINK; MCP-сервер поверх них — в дорожной карте.
6. **Модель для управления телефоном**: AutoGLM-Phone-9B (MIT, 20.6 ГБ в
   BF16) — на телефоне только после квантования; разумнее как узел ПК.

## Что требует ПК или внешней инфраструктуры

- Open-AutoGLM, DroidClaw, Mobile MCP — исполнитель работает на компьютере
  с подключённым по ADB телефоном.
- Phone-MCP — нужен свой relay (Cloudflare Workers или Node с HTTPS-туннелем).
- Mika, Zafiro, Nyral, OmniBot, OpenMinis, Aether — модели только облачные
  (по ключу или аккаунту); локальной модели нет.

## Вывод для NEXUS

Android Bridge NEXUS (Accessibility + Shizuku + Root с фиксированными
командами + снимок экрана с согласием + системные настройки) уже покрывает
основу. Главный пробел — **фоновое исполнение на виртуальном дисплее** и
**устойчивость агентного цикла** (детекторы залипания и повторов, передача
капчи). Обе вещи переносятся идеями, без копирования кода: лицензии Mika
(Apache-2.0) и Phone-MCP (MIT) это позволяют, а у DroidClaw нет файла
лицензии — его код не переносить (см. [аудит](08_RISK_LICENSE_AUDIT_RU.md)).
